# Política de revisão upstream e forks

- Verificar se a correção já existe no Android.
- Comparar SHA base/head e diff, não apenas nomes de branches ou versões.
- Avaliar dependências, licenças e alterações de API Vulkan.
- Não importar módulos inteiros quando alteração isolada basta.
- Não automatizar gameplay para reproduzir issues sem solicitação explícita.
- Registrar decisão: aproveitar, adaptar, aguardar ou descartar, com testes e risco.
- Evitar reanalisar forks sem mudanças relevantes.
